### F-12 · Rodar `pytest` suja a árvore de trabalho (Média) — reproduzido
- **Cadeia:** `pytest` → `analysis/tests/test_protocol.py::test_knob_map_13_of_14`
  executa `validate_knob_map.py`, que **reescreve** `analysis/knob_map.json` com
  `open(..., "w", encoding="utf8")` — em Windows o modo texto traduz `\n` → `\r\n`.
- **Evidência (medida nesta sessão):** após rodar a suíte,
  `git status` acusa `M analysis/knob_map.json` com **1005 CRs** e `git diff` **vazio**
  (conteúdo idêntico — só EOL). O repo normaliza para LF
  (`.gitattributes`: `* text=auto eol=lf`), então o arquivo fica "sujo" a cada rodada.
- **Por quê importa:** o próprio `.gitattributes` registra que "EOL faz parte dos
  bytes" e que conversão de EOL já mordeu o golden e o round-trip. Aqui o sintoma é
  ruído de `git status` (risco de commit acidental de EOL) e de `git add` parcial.
- **Recomendação:** escrever com newline explícito
  (`open(..., "w", encoding="utf8", newline="\n")`) no gerador, e/ou normalizar o
  arquivo uma vez (`git add --renormalize analysis/knob_map.json`).
- **Nota de higiene:** o arquivo foi restaurado ao HEAD nesta auditoria (conteúdo
  idêntico; só o EOL havia mudado).

> rodar a suíte afeta e registrar o veredito — **morto** (algum teste falhou) ou
> **sobreviveu** (a suíte não exercita a mudança). Cada mutante foi **revertido**
> antes do próximo; o estado final dos arquivos é o original + testes novos.
